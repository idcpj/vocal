# Vocal 致命避坑与开发铁律检查清单 (Critical Rules)

本文档整理了 Vocal 项目在多端开发中极易引发崩溃、死锁或重大异常的“血泪教训”，所有 Agent 及开发者在修改代码时必须逐项对照。

---

## 1. 致命红线 (Blockers)

### 🔴 铁律 1：iOS 26 真机严禁 Debug 模式
- **故障现象**: 真机启动或运行期间突然发生 `EXC_BAD_ACCESS` 崩溃并退出进程。
- **根本原因**: iOS 26 针对内存保护与调试符号增加了强制检测策略，Flutter 的 Debug 引擎在真机运行极易触发断言破坏。
- **强制规约**:
  - 针对 iOS 真机运行、调试、安装时，**必须强制添加 `--profile` 或 `--release`** 参数；
  - 正确命令：`fvm flutter run -d <DEVICE_ID> --profile`；
  - 严禁在任何脚本、CI 或指引中向用户提供未经 `--profile` 限制的真机运行命令。

---

### 🔴 铁律 2：Mac Accessibility 辅助功能权限必须健全防御
- **故障现象**: 文本无法打入目标窗口、程序卡死或抛出 `CGEventPost failed` 错误。
- **根本原因**: macOS 的 `CGEvent.post(tap: .cgAnnotatedSessionEventTap)` 受系统 TCC 安全沙盒保护，必须明确获取辅助功能授权。
- **强制规约**:
  - 在注入前必须通过 `AXIsProcessTrusted()` 校验权限；
  - 若权限未获取，需提供明显的菜单栏红点/警告，并弹出辅助功能授权设置引导；
  - 终端独立调试二进制文件时，需注意授权的是运行终端（Terminal 或 iTerm2），而非打包后的 Bundle。

---

### 🔴 铁律 3：语音草稿绝对不得自动发送或静音清空
- **故障现象**: 用户说到一半稍作停顿，半句话被强行打到 Mac 窗口或聊天框甚至被敲了回车发了出去。
- **根本原因**: 早期尝试过“单句识别结束自动发送”，但在真实输入场景下，用户经常需要停顿思考或修改错别字。
- **强制规约**:
  - 手机端采用“**本地草稿累加 + 用户手动确认发送**”原则；
  - 900ms 语音静音或识别停止仅代表关闭麦克风录入，草稿内容完整保留在 `textDraft` 输入框中；
  - 只有用户显式点击“发送到 Mac”按钮时，才会触发网络传输；发送成功后才清空草稿框。

---

### 🔴 铁律 4：双端协议任何变动必须保持向后兼容
- **故障现象**: 用户先升级了 Mac 端，手机端无法输入；或手机端升级后，旧版 Mac 端直接闪退。
- **根本原因**: 协议硬编码或序列化反序列化没有做兼容性容错。
- **强制规约**:
  - Mac 端必须永远保留纯文本降级处理能力（非 JSON 字符串直接输入）；
  - JSON 新增字段必须设为可选（Optional / Nullable），绝不依赖必须存在的未知键；
  - 心跳 Ping/Pong 必须独立处理，不可与业务文本数据帧混淆引发歧义。

---

## 2. 性能与资源防坑清单

1. **Mac 端 UI 与事件注入线程分离**:
   - `NWConnection` 回调在后台 Dispatch 队列；
   - 状态栏图标切换必须在 `DispatchQueue.main.async`；
   - `CGEvent.post` 必须确保在安全上下文注入，避免多线程重叠注入导致字符乱序。
2. **Flutter 内存泄漏排查**:
   - `VocalHomeController` 的 `Timer`（心跳计时器、重试定时器）在 dispose 时必须显式 cancel；
   - 语音识别 `speech_to_text` 的 listener 在不用时必须显式 stop / cancel。
3. **FVM 版本锁定**:
   - 禁止在未通过 FVM 的情况下随意使用系统级 global flutter 执行构建，防止版本漂移引发依赖冲突。
